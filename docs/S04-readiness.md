## Additional source findings that constrain the implementation

- No environment/PROD rejection exists inside `processor/*.js`, despite the handover's broad safety summary. S01/S02 guards must not be assumed to protect a future S03 endpoint. Add and test an explicit DEV-only project/sheet guard at that boundary.
- Idempotency compares a caller-supplied hash, runs before authentication and locking, and is lost when its Map disappears. Recompute a canonical hash over action/entity/version/payload and bind command identity to the authenticated actor. Recheck durable idempotency under lock; test altered payload with the same supplied hash, cross-actor replay, restarts and concurrent duplicate submissions.
- `computeChanges` accepts arbitrary payload fields; `applyChanges` writes commit_id=null. Restrict writable completion fields and propagate the commit ID to all affected records. Reject unexpected fields and command types rather than defaulting to FN-01.
- Recovery currently returns suggested actions; it does not durably resolve commits or prevent new commands on an unresolved task. The S04 path needs crash-point tests across task/event/audit/journal/result writes and must block unsafe replay while recovery is required. A Sheets write sequence is not an atomic transaction.
- `processCommand(null)` dereferences command before its try/envelope guard. Existing envelope tests alone do not prove endpoint malformed-input safety.
- Local tests named COMPLETE_TASK mostly prove generic processor acceptance. The separate helper test proves TaskEvents but not a committed end-to-end task action. Likewise the audit immutability test does not enforce immutable persistent storage. Do not claim those cloud properties yet.

## Transport decision and official platform constraints

AppSheet's native Call a script runs a **standalone** project, executes its head deployment, and runs as the app owner. Thus the existing Sheet-bound S02 project cannot simply be selected, and the executing identity does not prove who tapped Complete. Required plan/service availability must be checked. A future standalone data adapter needs explicit DEV sheet access and reviewed scopes; it must retain enumeration lookup and must not widen S02's scopes as a side effect. [Google: Call Apps Script from an automation](https://support.google.com/appsheet/answer/11997142?hl=en), checked 5 September 2026.

Google documents row-level filters using signed-in identity. Require Google sign-in and use Security Filters on each connected table, not slices. [Google: Limit users to their own data](https://support.google.com/appsheet/answer/10104977?hl=en). V8 supports modern JavaScript but is not a Node runtime; build an Apps Script global package rather than assuming require works. [Google: V8 runtime](https://developers.google.com/apps-script/guides/v8-runtime).

Before transport-specific coding, choose a trusted originating-user mechanism whose provenance the server can verify. An editable actor_email, a USEREMAIL initial value in a writable row, or app-owner Session identity alone is insufficient. The documented native-call capability does not establish an unspoofable originating-user assertion. If this cannot be established with available AppSheet facilities, specify an authenticated alternative within the Google architecture and stop dependent cloud wiring until resolved. Independent handler/persistence tests can proceed.

The draft/command-input table design is also unresolved: the current 60 tables have no dedicated command queue/result surface. Inspect whether an existing approved contract can serve it without semantic misuse; otherwise propose the smallest explicit migration separately. S02 closure and schema remain untouched by this audit.
